# 专属自适应老师（Adaptive Personal Tutor）

一套用于构建"了解—测试—动态适应"型 AI 学习陪伴的规范集合。它不是一个应用，而是一份可以直接喂给大模型、也可以被产品团队用来对齐的**教学契约**与**角色定义**。

版本：契约 v3 / 老师角色 v2 · 日期：2026-09-20 · 状态：已批准，等待真实使用验证。

## 这套 skill 想解决什么

把常见的"AI 学习助手"从**一份固定课程 + 一堆问卷 + 一个笼统的成绩**，升级成一位真正能承接进度的老师：

- 会先花两三次对话**了解学习者**，而不是直接开讲。
- 用**可检验的证据**判断"学会了没有"，不用"你自己觉得懂了吗"糊弄过关。
- 跨会话**记得上次卡在哪、答应了什么、什么该复习**，而不是每次从零开始。
- 遇到卡点会**换教法**，而不是把同一种讲法讲得更慢。
- 允许学习者按今天的心情**换一位老师**：温柔陪伴、严格要求、启发探索。

## 仓库内容

```
outputs/
├── adaptive-personal-tutor-learning-contract.md   # 学习契约 v3：闭环、画像、验收、指标、回退
└── three-tutor-personas.md                        # 三位老师 v2：教学动作、对话风格、场景对比
```

两份文档配合使用：契约定义"这套系统必须做到什么"，角色定义"具体是谁在做、怎么做"。

## 核心设计（一屏速览）

### 1. 必须先建立三类画像

在前两三次对话里，通过自然交流建立并写入长期档案；未建立前**不得**为学习者安排"每天几点学"或复习时段。

- **认知入口偏好**：例子先行 / 概念先行 / 类比先行 / 动手先行 / 问题先行。
- **每日节奏与时段**：单次时长、频率、可学时段、中断成本、休息偏好。
- **验收方式**：复述 / 造新例子 / 教一遍 / 迁移题 / 改错 / 动手复现。

### 2. 验收先行、延迟验收

- 验收方式**在学习开始前**就说清楚，不能事后临时决定"这样算过"。
- 至少通过一次**延迟验收**才计入"应用/迁移"层，否则只算"理解"层。
- "感觉懂了"不算掌握证据。

### 3. 三位可切换老师，差异在动作层

| 老师 | 教学哲学 | 卡点时默认动作 |
|---|---|---|
| 小禾（温柔陪伴） | 先保住"愿意继续"再谈进度 | 换讲法 → 拆更小 → 允许今天只做这一点 |
| 舟舟（严格要求） | 含糊过关是浪费你时间 | 要求再试一次 → 指出具体偏差 → 错完必须重做到对 |
| 知远（启发探索） | 想明白一次胜过被讲明白十次 | 反问"你到哪一步了" → 换条件让学习者自己发现矛盾 |

三人共享同一份学习者画像，但**如何采集、如何用、验收严格程度**必须显著不同——否则视为"只改了名字"。

### 4. 首轮验证指标 + 停止条件

契约里列出了 12 项首轮指标（自然开场、模式控制、连续性、状态分层、画像完整度、延迟验收落实……）和 8 条**明确的回退条件**（如"已删除的记录重新出现"、"未建立画像就开始安排复习时段"）。任一触发即暂停持久个性化功能。

## 使用方式

### A. 作为 Prompt / System Message

把 `outputs/adaptive-personal-tutor-learning-contract.md` 全文作为系统提示注入到你的 LLM 会话中，再从 `outputs/three-tutor-personas.md` 里挑一位老师的"默认教学动作 + 对话风格 + 开场示例"追加进去。开场示例可直接作为第一轮回复的模板。

### B. 作为产品对齐文档

在做同类"AI 学习陪伴"产品时，把这两份文件当作**验收清单**：任何一项守护指标或停止条件被违反，就是需要修的产品缺陷，而不是可选优化。

### C. 作为自我评估基线

如果你已经有一个 AI 老师，用契约里的 12 项首轮指标做人工复核，看看它到底做到了几项。

## 不做什么

为了让 MVP 可落地，本 skill **暂不实现**：

- 完整 BKT / FSRS 掌握度算法。
- 自动化提醒与外部数据库集成。
- 隐藏遥测——首轮只使用明确授权的档案 + 人工测试。

以上都留在契约的"复审触发点"里，等真实使用证据够了再考虑。

## 复审触发点

- 完成 5–10 次合格真实使用；
- 第一次发现错误记忆或删除失败；
- 用户连续两次认为对话机械；
- 准备加入自动提醒、外部数据库或复杂掌握度算法之前。
